1. ARCHITECTURE
----------------------------------------------------------------
Text encoder   : answerdotai/ModernBERT-base      (token-level sequence output)
Image encoder A: google/siglip2-base-patch16-224  (patch tokens + image/text
                 alignment embeddings for the cosine alignment score)
Image encoder B: facebook/dinov2-base             (patch tokens, fine-grained)

Fusion head (the only trainable part, ~3.87M parameters):
    T_seq      = proj_text(ModernBERT token sequence)              (B, L_t, D)
    V_img_seq  = concat(proj_siglip(SigLIP2 patches),
                         proj_dino(DINOv2 patches))                 (B, N_img, D)
    H_text     = mean_pool( CrossAttn(Q=T_seq,     K=V=V_img_seq) )
    H_img      = mean_pool( CrossAttn(Q=V_img_seq, K=V=T_seq) )
    g          = sigmoid( W_g [H_text ; H_img ; s_align] )          (gated multimodal unit)
    F          = g * H_text + (1-g) * H_img
    logits     = MLP( [F ; s_align] )

All three encoders are FROZEN (no fine-tuning) -- this is a two-stage
pipeline specifically designed to fit a 6GB laptop GPU:
  Stage 1 (extract_features.py): runs the three frozen encoders once,
           one at a time, no gradients, caches outputs to disk.
  Stage 2 (train.py): trains only the small fusion head on the cached
           tensors. The big encoders are never loaded in stage 2.

3. BUG FOUND AND FIXED DURING THIS RUN
----------------------------------------------------------------
File: extract_features.py (SigLIP2 stream)

Problem: in the installed transformers version, model.get_image_features()
and model.get_text_features() return a BaseModelOutputWithPooling object,
not a raw tensor as the original code assumed. This crashed the smoke
test with:
    AttributeError: 'BaseModelOutputWithPooling' object has no attribute 'float'

Fix: verified live against the actual loaded SigLIP2 model, then changed
both calls to read `.pooler_output` from the returned object. Re-ran the
smoke test (50 samples) end-to-end afterward to confirm the fix -- passed
cleanly with the expected tensor shapes.

7. ABLATION STUDY -- TEXT-ONLY AND IMAGE-ONLY BASELINES
----------------------------------------------------------------
99.93% accuracy is unusually high for a fake-review detection task, so
the two ablations recommended in the architecture doc and the README
were run: text-only (image stream + alignment score zeroed) and
image-only (text stream + alignment score zeroed). Same cached features,
same fusion-head architecture and training recipe, only the input
masking differs.

Command:
  python train.py --features features --out runs/ablation_text_only  --ablation text_only
  python train.py --features features --out runs/ablation_image_only --ablation image_only

 Model          | Test Acc | Test Prec | Test Recall | Test F1 | Epochs to best
 ---------------|----------|-----------|-------------|---------|----------------
 Full fusion    |  99.93%  |  99.85%   |   100.00%   |  99.93% |  7  (of 12 run)
 Text-only      |  99.83%  |  99.90%   |    99.76%   |  99.83% |  6  (of 11 run)
 Image-only     |  99.21%  |  99.03%   |    99.41%   |  99.22% | 18  (of 20 run)

Conclusions:
  - Text alone already gets very close to the full model (99.83% vs
    99.93% F1) -- text is the dominant signal for distinguishing
    human-written from AI-generated reviews in AiGen-FoodReview, and
    this dataset is genuinely easy on the text side (consistent with
    it being reported as an "easy" benchmark in the literature).
  - Image alone is noticeably weaker (99.22% F1) and needed the full
    20-epoch budget to get there, confirming images carry a real but
    smaller and harder-to-extract signal than text.
  - The 99.93% full-fusion number is NOT just "the easy modality
    alone" -- cross-attention fusion recovers the ~0.1 point gap on
    top of the text-only baseline (helped by the SigLIP2 image-text
    alignment score, the gated combination, and the dual-stream
    patch features). The improvement is small in absolute terms
    because this dataset is close to saturated by text alone, but it
    is a real, measured effect, not an unverified assumption.
  - None of this points to a data leak: train/val/test come from
    disjoint CSVs and features were extracted independently per split.

One engineering note from running these: the first text-only attempt
crashed with a Windows-specific DataLoader multiprocessing error
(RuntimeError: Couldn't open shared file mapping..., error code 1455 --
a page-file/shared-memory limit, unrelated to the model code). It was
not reproducible on retry with --num-workers 0 (single-process data
loading), which is what the reported text-only numbers above use. If
this recurs on your machine, pass --num-workers 0 to train.py.

8. SIMPLIFICATIONS MADE (for the writeup)
----------------------------------------------------------------
- Text encoder is ModernBERT-base, not Qwen3-Embedding (Qwen3-Embedding
  is pooled-only and does not suit token-level cross-attention as-is).
- Image patch tokens pooled to a 4x4 grid (16 tokens/stream) to keep
  cross-attention and disk cache laptop-sized; --pool-grid can be raised
  later for a higher-resolution final run.
- All three encoders kept frozen; no LoRA fine-tuning in this version.
